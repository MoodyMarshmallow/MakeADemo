# Use Demo Scripts for Event-Marked Capture

MakeADemo will replace the legacy Video Script Package handoff with a Demo Script that centralizes the demo Playwright flow, declared Scenes, expected outcomes, and presentation metadata. We chose this because agent-authored per-Scene durations caused final videos to freeze short captures and truncate long captures; a continuous event-marked Demo Script lets setup happen off-camera while Footage Capture derives actual Scene durations from capture-harness marker events.

The Demo Script will use a real Capture SDK Contract provided as MakeADemo-owned generated harness files, not prompt-only syntax or agent-inlined marker helpers. Footage Capture will run the Demo Script from a fresh deterministic starting state, preserve browser and app state across Scenes, record one continuous take, and trim that take into per-Scene clips for Compositing. Capture Path Validation will run the same Demo Script once from a fresh deterministic state with the same sequential typing, coordinate click, hover, scroll, and pointer helpers, but validation disables presentation timing and scroll cues. The pointer helper remains present with its movement duration set to zero. Validation does not record video, add post-roll, download capture artifacts, or trim footage.

This is a clean cutover rather than a compatibility layer for old Video Script Package artifacts. The tradeoff is that implementation must update Script Generation, Capture Path Validation, Footage Capture, and Compositing together, but the pipeline avoids carrying two competing script models through every stage.
