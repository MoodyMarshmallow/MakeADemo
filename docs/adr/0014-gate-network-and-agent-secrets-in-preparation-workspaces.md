# Gate Agent Secrets; Defer Runtime Network Lockdown

The agent may have broad Harness-provided coding capabilities inside the ephemeral workspace, while the submitted app runtime remains in a separate Daytona sandbox. During development, both sandboxes are intentionally created with `networkBlockAll: false` (subject to Daytona organization-level egress policy); Daytona sandbox-firewall Runtime Network Lockdown is deferred rather than enforced. We chose this temporary tradeoff because the small tool needs a simple always-networked development path, while submitted repo code must still not inherit agent privileges or secrets. Browser-level request interception remains available for deterministic evidence but is not full sandbox-boundary isolation.

Dependency installation remains backend-controlled and uses only the exact immutable command in the resolved toolchain plan, but it does not open or reseal a temporary network window. The agent-facing install tool is argumentless: repository or model-authored command text and flags cannot select what executes. The Daytona sandboxes already have network access under the development policy; a future lockdown implementation may restore dependency-install-only windows as a separate hardening step.

Outbound network access is not blocked after dependency installation in the current development policy. Demo build, demo start, Capture Path Validation, and Footage Capture run in the isolated sandboxes with network available until Daytona sandbox-firewall Runtime Network Lockdown is implemented. Browser-level request interception and blocked-network markers remain active where the capture/validation seam supports them.

Agent research tooling belongs to the backend Agent Harness rather than the Daytona workspace or submitted app runtime. The Harness exposes anonymous Exa MCP web search and fetch tools through the official MCP SDK and loads Context7's official Pi extension explicitly; neither integration requires an API key during development. Research endpoints are fixed by the Harness, their results are untrusted input, and submitted repositories cannot add MCP servers or agent extensions.

Agent-authored shell and file operations in the parent preparation workspace run as an unprivileged image user and cannot mutate trusted helpers or package runtimes. The agent may edit `/workspace`, but file operations reject canonical paths changed by symlinks. Submitted dependency, build, and runtime execution remains behind backend-owned submitted-code-sandbox methods; command text inspection is not an authorization boundary. The separate sandbox is an isolation boundary even while its network remains enabled.

LLM provider credentials and any future agent-only secrets remain only in backend memory and are supplied directly to Pi's model runtime. They must not be injected into Daytona. Demo build and runtime subprocesses continue to receive a scrubbed environment, and persisted logs must redact secrets.
